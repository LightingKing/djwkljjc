## 必须登记的 D / 本地规则

- 上述活动常开、20 个 UP 同时可选是用户授权的本地排期，历史排期未恢复。等级、前置限制、已有日次数和付费成本继续遵循既有实现。
- 活动 13 开放时，普通和限定池每实际抽取 1 次给 1000 书签积分；包括原免费抽。数值 1000 来自 Misc，适用池及发放条件是 D / 本地。扣费、角色、保底、积分与重放凭据在同一事务提交，失败整体回滚。
- 未找到原积分商店库存；商品放在 `data/server-only/gacha-score-shop.json`，绝不混入标记原版来源的表。永久账号一次：100000 积分换紫色角色 1001、100000 积分换紫色角色 2001、50000 积分换皮肤 100104。商品 ID 分别为 1300101/1300102/1300103；价格及库存为 D / 本地。只售客户端支持的角色/皮肤；100104 为已上线且资源齐全的原皮肤。
- 积分商店已买商品永久下架，不按周期重置；重复提交返回空 resChange，不扣第二次积分。其他渠道已获得的皮肤也下架，强行请求返回原生错误，不能重复扣点。库存固定不刷新，`next_refresh_time=2147483647` 是本地永久库存的协议值。
- 活动竞速与普通竞速共用票据、赛季、房间、排行及领奖账本；开关 type42 不新造一份奖励。客户端没有活动 ID 请求字段，因此以当前可用排期决定新房间主题；已创建的房间保留原主题。内部赛季时段与已有竞速规则保持一致，常驻入口不等于取消赛季结算。
- 原 ApiGachaTrade 没有 nonce；本地客户端新增 query `localRequestId`，由玩家、北京时间 06:00 游戏日、池 ID、服务端每日累计次数组成。服务端持久化规范化请求与原始响应；同键同参重放、异参拒绝。原远端 Post 分支完整保留。网络重试/服务端重启可重放；客户端重启并重新获取最新次数后的新点击按新付费操作处理，不宣称能自动识别所有用户重复点击。未带键的旧客户端仍按每次成功请求处理新抽取。
