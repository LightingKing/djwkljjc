# 路由与契约覆盖

`server/core/routes.py` 是 M3.1 的独立路由基础设施。它从 `contracts/api.yaml` 载入接口描述，按接口名注册业务处理器，并把路由分发结果统一成 `RouteResponse`。

已知接口没有处理器时会返回 `501 route_not_implemented`，同时按接口累计调用次数；完全未知的路径返回 `404 route_not_found`。`<string:name>`、`<int:name>` 和 `<path:name>` 路径参数会被解析并传给处理器。处理器异常会转换成不泄露异常内容的 500 响应。

`coverage_report()` 返回总接口数、已注册接口数、覆盖率、未实现调用计数、未知路径计数以及逐接口状态，可直接用于本机管理页或回归报告。服务启动时，账号相关的 `AccountSession`、`EntryReg`、`Account`、`Auth`、`Password`、`PasswordReset`、`AccountGuestBind` 会通过 registry 绑定到兼容处理器；其它业务模块仍按批次迁移。

验证：

```text
python -m unittest discover -s tests -p test_routes.py -q
```

当前契约表有 84 个接口；目录/版本控制面、账号、状态探针和部分玩家接口已经注册 68 个本地处理接口，回环覆盖率端点会实时显示当前注册数。剩余 16 条是 GM、外部身份或服务端管理接口，保持明确的 501 边界，原因见 [docs/安全契约边界.md](安全契约边界.md)。路由基础设施的单元测试覆盖动态参数、501 计数、404、注册替换和覆盖率报告。独立契约 harness 会为 84 条契约生成确定性 smoke 请求和 JSONL 回放记录。


## 本地诊断端点

服务启动后，`GET /__local__/coverage` 返回契约总数、已注册数、501 调用计数和逐接口状态；`GET /__local__/route-table` 返回可序列化路由表。两个端点只接受 `127.0.0.1`/`::1` 的请求，即使游戏监听器绑定到了局域网地址也不会把管理诊断暴露给手机。
