# M6.6 实时 PVP 本地兼容子集

## 范围

`LocalRealtimePvp` 为已经停服的 RacePVP 和 BurstLink 提供可重复的本地机器人对战状态机。它保留客户端需要的生命周期：查看信息、匹配、逐回合出牌、结算和重连查询。实现使用本地 SQLite，服务端不连接官方或第三方服务，也不修改客户端反作弊/完整性逻辑。

## 路由

两种模式都接受以下 JSON 入口（路径大小写不敏感）：

| 操作 | RacePVP | BurstLink |
| --- | --- | --- |
| 状态/票券 | `GET /fci/racepvp/info` | `GET /fci/BurstLinkPvpInfo/` |
| 匹配 | `POST /fci/racepvp/match` | `POST /fci/burstlink/join` |
| 查询当前局 | `GET /fci/{mode}/match/{matchId}` | 同左 |
| 回合 | `POST /fci/{mode}/match/{matchId}/round` | 同左 |
| 结算 | `POST /fci/{mode}/match/{matchId}/balance` | 同左 |

`round` 的请求体可带 `{"round": 1, "action": "attack"}`。动作支持 `attack`、`skill`、`defend`、`support`、`wait` 和 `auto`。缺少回合号时按下一回合处理；重复提交同一回合返回 `duplicate=true`，跳过回合返回 409。

## 本地规则与来源

- RacePVP：8 回合、5 名参赛者、每日 6 张票。
- BurstLink：5 回合、玩家加 2 名机器人、每日 1 张票。
- 规则参数来自 APK 中观察到的 `data/config/Misc.json`（`racePVPRoundNum`、`maxRacePvpPlyNum`、`racePVPTicketNum`、`burstPvpMatchMaxWaitTime` 等）。缺失的官方结算表使用明确标记的本地沙盒值：胜利奖励 100 金币，失败奖励 40 金币，RacePVP 评分胜负变化分别为 +25/-15。
- 机器人、动作和分数由账号、局号、回合号的 SHA-256 种子计算，重启后结果一致。

结算会通过现有资源账本一次性发放金币；重复结算只返回首次结算结果，不会重复发放。局状态和历史记录保存于 `local_realtime_pvp_state` 表。状态读改写在同一请求期间持有数据库旁路锁（`<db>.process.lock`）和进程内锁，多个本地 worker 同时匹配或推进回合时会按顺序处理，避免票券、局号和回合状态丢失。该机制不把机器人兼容子集扩展成官方实时服务，也不支持跨机器真人对战。

## 验收

`tests/test_realtime_pvp.py` 覆盖匹配幂等、回合顺序校验、重复回合、自动结算、重复结算、票券耗尽和重启持久化；`tests/test_cross_process_state.py` 进一步覆盖多个独立 worker 同时创建同一账号的比赛时只消耗一张票、保留一个局号。它们验证的是本地兼容行为，不代表已经恢复官方实时对战服务器或历史数值。
