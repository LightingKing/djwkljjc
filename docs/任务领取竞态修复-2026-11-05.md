# 任务领取后其他待领取任务消失：修复记录

## 结论

服务端没有删除另一个待领取任务。普通任务 `3` 和 `4` 同时完成后领取 `3`，`LocalTasks._payload()` 仍返回任务 `4`，且 `delTasks` 不包含 `4`。从正式服共享存档回放 `60017`/`60018` 也得到相同结果。该项属于客户端任务卡领奖回调与 `ScTasksChange` 推送同时写本地任务列表时的竞态。

## 修复

`client-patch/hot-update/sources/widgettaskslot-v24.lua` 保留领奖结果和活跃度的即时更新，移除对缓存任务分类列表的 `table.remove` / 重新插入。领奖回调最后重新 GET `fci/task/`，交给 `Common/TaskUtil.InitData` 按完整服务端快照合并。这样推送先到或 HTTP 回调先到都使用同一份权威任务投影，其他待领取任务不会被局部列表写覆盖。

候选配置为 `client-patch/hot-update/modules-task-fix-v23.json`，基于已发布 v22，只覆盖 `assetbundle/data/lua/window/task/widgettaskslot`。`source-origins-task-fix-v23.json` 记录原包 SHA-256。它是隔离候选，不能单独覆盖后续角色补全候选；正式发布时应并入下一条实际发布线并重新构建对应版本。
