## 45 练度竞赛

- A：`xlsx__challengemodedungeon.lua` 原表 20 行；45001–45010 包含 30 个不同关卡，45011–45020 的关卡组合重复前十。`ChallengeModeDungeon.json` 保留原值及原模块 SHA256。
- D / 本地：入口常驻，按北京时间周一 06:00 轮换 45001–45010，锚点为 2026-11-02 06:00（1793570400）。不把 20 个赛季同时塞进原客户端的有限页签。上一周已入场的战斗仍可按入场快照结算。
- A：`window__actorgroupcultivationpvp__actorgroupcultivationpvp.lua:127–155` 提交 `isChallengeMode=true`、每角色千分比 `reduceInfo`，并以 Normal 类型进入原关卡。`window__city__city.lua:321–355` 使用 `scoreRecord` / `rewardRecords`，条件为玩家最低分不大于奖励阈值。
- D / 本地评分：`sum(ceil((20*level + 100*star + 10*quality) * ratio/1000))`，每名上阵角色至少 1 分。49 个固定机器人提供可重启恢复的排行榜；分数取负以匹配原 UI 排序。这不是原版培养评分复刻，客户端原评分预览与本地榜单分值可能不同。
- A + D：原客户端 `common__windowutil.lua:1209–1248` 直接把服务端六席 actors 放进 FightActorInfo；`common__actorutil.lua:1009–1056` 给出了属性/技能/天赋的比例取整和最低 1 规则。服务端入场冻结队伍与比例，缩减 HP、攻击、双防、暴击率、暴击伤害及技能/天赋等级，避免仅降低计分却不降低战斗属性。具体离线实现仍标 D / 本地。
- 原普通关卡的消耗、奖励与终局状态机继续复用。`mode=cultivation` 区分活动和普通入场；普通通关不会产生练度记录。真实 FightActiveData 的 stage/type/round/终局经过校验，胜利结算与最低分写入同一 SQLite 事务。终局后 DELETE 会先结算，重复 balance 使用原缓存。
- A：270 行 `ChallengeModeScoreReward` 原奖励未改；领取记录按关卡和阈值永久幂等，十周后同赛季再次出现不会再发已领积分奖。奖励和领取标记同事务，失败回滚。
- `/challenge-mode-rank/top/<n>/dungeon/<id>` 返回本周榜；`/challenge-mode/season/<id>` 返回该关最近一个已参与的旧周期榜。永久积分奖和周期排名分账保存，不宣称恢复已退休的历史全球赛季数据库。
- A：`ChallengeModeRankReward.json:1` 的 type=1、名次 1/2/3/4–10/11–50 分别发 70001/70002/70003/70004/70005 一枚；`MedalInfo.json:1` 的这些徽章 `expireDay=28`。周期奖走原邮箱领取后，现有徽章逻辑按领取时起算 28 天。
- D / 本地周期结算：只对本周实际胜利的关卡在下周一 06:00 冻结排名，创建“练度竞赛赛季排名奖励”邮件；每周期每关一次。登录或认证请求补算离线时实际参与的周期，没有参与的周不造奖励。迟到胜利可改善永久积分，但不改已冻结的排名奖；观察到的周期单调，时钟回拨不能重新入场旧周期。邮件沿用本地邮箱创建后 30 天有效期。

## 49/50 公会副本

- A：`GuildDungeon` 8 行、`GuildDungeonAssistScoreReward` 4 行、`GuildDungeonChallengeScoreReward` 12 行、`GuildDungeonChallengeProgressReward` 12 行直接从原模块导出；没有修改原数值。

- A：原枚举 `GuildChallengeDungeonStatus` 为 Close=1、Open=2、Unopen=3；`window__dungeonguildstage__dungeonguildstage.lua` 按该状态互斥展示协助/挑战。
- D / 本地：周一 06:00–周六 00:00 为协助（6101–6105 都可打），周六 00:00–周一 00:00 为挑战，周一 00:00–06:00 为结算。挑战关卡 6001–6003 按 `(weekStart // 604800) % 3` 轮换，入口持续可见，不宣称两种互斥玩法可同时作战。
- D / 本地：已有本地公会的五名机器人每周每关各贡献基础总 HP 的 10%，合计 50%；真实玩家造成剩余伤害。机器人身份复用公会成员，展示分数不会伪造玩家资产。共享伤害、个人最高分、完成次数、领奖、战斗终局缓存持久化。玩家须在对应挑战关结算过，才可领取其进度奖；同账号每周同档只可领取一次。
- 胜利或失败的有效终局都按实际伤害结算；原客户端先 DELETE 再 balance 的顺序会先原子结算并保存缓存，重复 DELETE/balance 不重复加伤害或完成次数。保存失败时共享伤害、个人记录和终局一起回滚。
- A：`window__dungeonguildstage__dungeonguildstage.lua:249–310` 明确使用前三名分数总和 S（包含机器人），`GuildDungeon.json:1` 给出原参数。令 E=max(0,S-scoreDelta)，共享公会人气=min(scoreUpLimitForGuild,E×exchangeScaleForGuild//10000)，个人贡献=min(scoreUpLimit,E×exchangeScaleForPerson//10000)；原上限分别 25000/500。贡献采用原 `ResourceType.ResGuildScore=17`，共享人气写入公会 baseInfo.score。
- A + D：按原 challengeBuffs 阈值取最高一个 501/502/503，不叠加档位；`ProfitDetail` 原值 type=3、加成 500/1000/1500 万分比、dungeonType=[2]、time=608000 秒。公会成员实际普通关卡角色经验分别增加 5%/10%/15%。本地时间从周期周一 00:00 结算点开始，离线补算不延长期限；重叠周期只投影最近一个有效周期。该 Buff 为公会范围，未参战的当前成员也享有。
- D / 本地发放：只在至少一名真实玩家在挑战中结算正伤害的周期发共享人气和 Buff；只有实际参与者获得“公会副本周期贡献奖励”邮件，离线成员后续登录单独补发，各账号一次。纯机器人周期不产出资产。共享人气、成员贡献记录、个人邮件和周期收据同事务；全局观察时间单调，回拨不能重结算或复活过期 Buff。邮件沿用本地邮箱创建后 30 天有效期。
