# M2.5 协议面审计

`tools/audit_protocol_surface.py` 将三种证据分开统计：IL2CPP 类型名、HTTP protobuf 描述符，以及运行时日志中的 WebSocket 消息名。这样可以回答“发现了多少协议对象”和“本地实现了多少路由”，但不会把两者混成一个恢复率。

## 当前结果

生成文件：`analysis/protocol-surface-audit.json`。

- IL2CPP 类型名中的 `Api*` 原始数量、排除 `Api`/`ApiReflection` 运行时辅助类型后的候选数量，分别记录在 `counts.apiTypesRaw` 和 `counts.apiCandidates`。
- HTTP 描述符当前有 84 个接口，来源是 `analysis/ljjc-local/protocols/interface-map.json`。它是当前契约底稿，不代表路线图里预估的全部接口数量。
- IL2CPP 类型名原始包含 32 个 `Cs*` 和 65 个 `Sc*` 前缀名；其中 29 个是 `Scene*`、`Script*`、`Scroll*` 等 Unity/.NET 类名碰撞，过滤后得到 68 个协议候选。原始前缀清单和被过滤项都保留在报告中。
- `runtimeEvidence` 只从证据目录中的 `.jsonl`/`.ndjson` 记录提取；`descriptor_set.json`、静态协议说明、反编译笔记和其它 JSON/TXT 不会被当成运行时抓包。当前 68 个候选中只有 10 个有运行时 JSONL 证据。报告的 `sources.runtimeEvidenceFiles` 记录实际采信的文件，便于复核。
- 本地 HTTP 实现状态仍以运行时 `RouteRegistry.coverage_report()` 为准；WebSocket 只完成本地机器人/兼容子集，不能宣称官方实时服务恢复。

运行：

```powershell
python tools/audit_protocol_surface.py -o analysis/protocol-surface-audit.json
```

如果换了分析目录，可通过 `--type-names`、`--interface-map` 和 `--evidence-root` 显式指定输入。缺少输入时脚本会失败，不会生成猜测数据。

协议消息名的前缀在 Unity 类型系统中并不唯一，因此 `csTypesRaw`/`scTypesRaw` 不能直接用作协议数量；验收时应使用 `protocolTypeCandidates` 和 `runtimeWebsocketEvidence`，并检查 `excludedPrefixCollisions` 是否来自可解释的类名碰撞。
