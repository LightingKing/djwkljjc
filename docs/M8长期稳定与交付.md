# M8.3 长期稳定与 M8.4 交付

## 长期稳定回归

`tests/test_long_term_stability.py` 提供三个可重复用例：

1. 读取玩家档案时按 `data/server-only/economy.yaml` 的本地规则恢复体力，恢复量受上限限制，并在同一事务中写入 `local_resource_ledger`；同一时间重复读取和重启进程不会重复发放。
2. 用注入的 `ServerClock` 连续模拟 28 个 06:00 日切（29 次登录，覆盖完整四周周期），逐日重启 `LocalGame`，验证签到、月卡沙盒奖励和体力恢复；同时验证跨过四个周边界的周桶计数。
3. 在 28 天活动周期的起点、第 7 天和下一周期起点检查排期快照，确认活动轮换是确定性的。
4. 由 `tests/test_cross_process_state.py` 启动 8 个独立本地 worker 并发写入社交状态，确认数据库旁路锁不会丢失聊天消息；该测试只覆盖同机多进程一致性，不代表跨机器联机。
5. 额外覆盖管理面板把本地时钟向后调整的边界：恢复标记会重新锚定，不会把调整前的时间段重复铸造成体力；`dev/m8_acceptance.py` 同时纳入 `test_clock.py` 与 `test_activity_schedule.py`。

运行方式：

```powershell
python -m pytest -q tests/test_long_term_stability.py
```

统一验收脚本可把长期回归、契约 smoke、交付包清单和临时解压健康检查合并成动态 JSON 证据：

```powershell
python dev/m8_acceptance.py --run-tests --health-check --output runtime/m8-acceptance-report.json
```

报告记录命令退出码、交付包 SHA-256、逐文件清单哈希、敏感条目排除结果、本地实现与 501 安全边界审计，以及 M4–M6 本地玩法烟测结果；它还会检查临时实例的 /__local__/health 和接口覆盖数量。报告写入 runtime/，不会进入交付包；客户端 G1/TPShell 状态仍由客户端验收文档单独记录。

体力恢复是本地兼容规则，来源和置信度仍以 `data/server-only/economy.yaml` 为准。原服务端已关服，无法把这些值宣称为官方历史数据。

## 离线交付包

`tools/package-offline.ps1` 生成可复制的服务端源码包和使用文档：

```powershell
.\tools\package-offline.ps1
```

也可以指定输出路径：

```powershell
.\tools\package-offline.ps1 -Output .\delivery\ljjc-offline-server.zip
```

脚本兼容 Windows PowerShell 5.1 和 PowerShell 7；在 PowerShell 5.1 中直接从仓库根目录执行上面的命令即可。生成后应检查命令输出的文件数，并确认压缩包中没有 APK、签名材料、`runtime/`、`analysis/`、数据库、日志或截图。生成后可运行上面的验收脚本，自动检查敏感条目和清单哈希。

压缩包内包含源码、配置、契约、测试、工具和文档，并在根目录写入 `DELIVERY-MANIFEST.json`（文件 SHA-256 和大小）。运行时需要的 `data/descriptor_set.pb` 也会被纳入白名单；脚本明确排除 APK、客户端构建输出、私钥/证书、SQLite 存档、运行时状态、备份、日志、截图、Git 元数据和缓存，因此不会把个人存档或签名材料带进交付包。

交付包只代表本地服务端和工具链。客户端空补丁仍受 TPShell 完整性链路阻断，不能把它标成客户端 G1 已通过；实时 PVP、完整机器人公会和官方历史内容也必须按路线图的边界说明。
