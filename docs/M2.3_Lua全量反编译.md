# M2.3 Lua 全量反编译审计

这一步先把输入、格式和阻塞点固定下来，避免将受保护的 `FCI\0` 载荷误报为源码。

## 当前证据

- `data/apk-inventory.json` 中有 **858** 个 `assets/Patch/assetbundle/data/lua/*` 模块路径。
- `analysis/ljjc-lua-extract/` 当前有 858 个平铺文件，但它们的前缀是 ASCII `FCI\0`。这是资源包保护载荷；本仓库没有恢复该资源加密密钥和解码步骤，因此不能安全交给反编译器。
- `analysis/ljjc-local/lua-runtime/` 中已有一批运行时转储，前缀为 `00 66 63 69 01`。该布局已经用探针验证了 Lua 5.3 opcode 映射，可由外部的单文件转换器静态反编译。
- 运行时转储的反编译结果仍需抽样重编译和运行时加载验证；仅有反编译文本不能证明字节码等价。

## 可复现命令

```powershell
python tools/audit_lua_decompilation.py `
  I:\workspace\mobilegame\analysis\ljjc-lua-extract `
  --output-root analysis/lua `
  --output-report analysis/lua/decompilation-audit.json `
  --inventory data/apk-inventory.json
```

如果要处理已验证的运行时转储，显式提供单文件转换器；工具只会对 `00 66 63 69 01` 输入调用它：

```powershell
python tools/audit_lua_decompilation.py `
  I:\workspace\mobilegame\analysis\ljjc-local\lua-runtime `
  --output-root analysis/lua `
  --output-report analysis/lua/runtime-decompilation-audit.json `
  --converter I:\workspace\mobilegame\runtime\ljjc-lua\decompile.py
```

每个文件都会记录 SHA-256、布局、状态、转换器退出码和错误输出。受保护资源会标记为 `blocked_protected_payload`，不会生成伪造的 `.lua` 文件。工具不执行 Lua，也不修改输入文件。

## 验收边界

M2.3 只有在资源保护层被独立恢复、批量转换结果全部有来源哈希，并且抽样完成“解码 → 反编译 → 重编译 → 原运行时加载”闭环后才能标记为完成。当前可交付的是可重复审计和明确阻塞证据，不能宣称 858 个模块已经恢复成源码。
