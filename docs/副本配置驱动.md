# 副本配置驱动

`server/core/content.py` 读取 `data/config/ChapterInfo.json` 和
`data/config/DungeonReward.json`，并保留表的来源、观测行数和是否完整。`dungeon.py` 的本地章节 ID
来自这些表，不再在副本模块里直接写 `range(1, 9)` 作为唯一来源。

当前提取结果的元数据报告 ChapterInfo 观测到 35 行、DungeonReward 观测到 683 行，但仓库只保存了
前 6 行样本。因此“完整官方章节”仍未恢复；本地兼容层会开放仓库中这 6 行实际存在的 87 个普通/挑战
关卡 ID，允许逐关进入并按明确的本地策略结算。`DungeonConfig.supported_normal_ids` 仍保留第一章 1–8
作为资源验证标记，`DungeonConfig.all_normal_ids` 才是本地入口使用的全部观察 ID。2011/2012/2013 来自
DungeonReward 中的故事奖励行。

奖励读取规则是：如果恢复的 DungeonReward 行有明确的玩家 EXP 字段（`expPlayer`、`playerExp` 或
`exp_player`），优先使用该字段；当前样本没有这种无歧义字段，不能把 `expActor` 或展示掉落误当成
玩家经验，所以 2011、2012/2013 和首章普通关使用 `data/local-defaults.json` 中带 provenance 的
本地兼容策略。未知副本不会凭空生成掉落或经验，仍返回未实现状态。旧版本存档中的零经验结算不会
在服务启动时被隐式补发或改写。

表文件缺失时，加载器使用 1–8 和 2011/2012/2013 的显式兼容回退，并在 `provenance()` 中报告
`fallbackUsed`；这条路径只用于开发环境缺少抽取数据的情况。

验证：

```powershell
python -m unittest discover -s tests -p test_dungeon_config.py -q
```

## M5.5 特殊副本规则

金币本、爬塔、迷宫和锦标赛 PvE 使用 `data/server-only/special-dungeons.yaml` 作为本地沙盒规则源。服务启动时读取其中的阶段 ID、体力消耗、奖励和层数上限；响应会带 `policySource` 与 `provenance`，便于区分本地规则和已恢复的客户端配置。文件缺失或格式无效时只回退到代码内同值的审阅规则，不会从未知 ID 推测官方副本。
