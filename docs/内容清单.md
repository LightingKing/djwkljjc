# 内容上限核对

这是 M2.8 的可重复核对入口。状态描述资源是否已经在当前工作区确认，不代表已恢复原官方服务端。

可以用下面的命令重新生成资源证据报告：

```powershell
python tools/audit_content_coverage.py `
  --inventory data/apk-inventory.json `
  --config-dir data/config `
  --output data/content-audit.json
```

`data/content-audit.json` 只记录 APK 清单路径和配置行之间的可追溯字符串匹配。配置表标记为 `partial` 时，即使所有已观察行都找到资源，也仍然保留 `partial`，避免把运行时样本误写成全量内容。

配置资源覆盖的第二份证据见 `data/config-source-audit.json`。当前 APK 清单有 208 个 `data/lua/xlsx` / `data/xlsx` 资源路径、
187 个归一化表名；只有 19 个表名与 `data/config` 的 29 张运行时抽取表重合，168 个表名仍是
`asset_only`，另外 10 张抽取表没有同名 APK 路径。4 个非 xlsx 的配置候选路径单独记录为
候选组件，不参与表数量统计。资源路径只证明清单中存在名字，不能证明 AssetBundle/Lua 已解码；
受保护 `FCI\0` 载荷在取得合法解码证据前保持缺资源状态。
