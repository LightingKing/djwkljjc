## 2. 硬性规则（沿用前几轮）

1. **完成的标准**是在真实客户端原生界面里走通，并附截图、请求日志、logcat。只有自动化测试的项，一律写“仅自动化”。实机验收由用户本人进行，不要代写结论。
2. **全量测试必须在要发布的那个提交上跑**，0 失败，附提交号。不允许删测试，也不允许放宽断言。
3. **禁止直接修改发布目录（release worktree）**。改动先提交，再从干净提交发布。
4. **数值优先用原版**。本地规则写进 `docs/本地规则清单.md`。不准往标注“original APK”出处的表文件里塞非原版数据。
5. 补丁**不得删除客户端原有内容或入口**。充值只做沙盒。
6. **不得重签名 APK，不得绕过或关闭 TSS / 完整性保护**。手机方案只能用原版签名 APK。
7. 验收只用隔离模拟器和隔离账号，不动用户的正式存档。

## 4. P1

### P1-1 让同一个服务端同时服务模拟器和手机

- **现状**：
  - 回包里的地址都来自固定的 `public_base_url`。
  - 模拟器的 iptables 只允许游戏访问 127.0.0.1，所以不能简单把 `public_base_url` 改成局域网 IP。
  - v18 补丁 `IsLocalAccountServer` 写死了 `192.168.1.22`，电脑 IP 一变，登录和充值就失效。
- **要做**：
  - 服务端按请求的 Host 决定回包地址。只接受回环或私有网段（RFC1918），并且端口必须是本服务的端口；不符合的回退到配置值。目录、配置、推送 URL、补丁清单里的 ZIP 下载地址都按这个规则改写。
  - 补丁里的 `IsLocalAccountServer` 改为：回环地址或私有网段，加上本服务端口，不再写死某个 IP。
  - `dungeon.py:1677` 组队副本地址写死了 `ws://127.0.0.1:19102`，改为根据请求地址生成。
  - 加测试：同一进程里，分别用 127.0.0.1 和 192.168.x.x 访问，拿到的地址各自正确；公网 Host 必须回退到配置值。
