## 服务端证书续签

1. 在隔离临时目录生成新的服务端密钥和 CSR，保留上面的三个 SAN。服务端证书的 `-days` 或显式 `-enddate` 必须不晚于 CA 的 `notAfter`。
2. 用 `analysis/ljjc-local/certs/new-20261103/ca-key.pem` 签发，并用 `openssl verify -CAfile ca.pem server.pem` 验证链；用 `openssl x509 -checkend 0` 验证尚未过期，用 `openssl x509 -text` 核对 SAN。
3. 先备份当前 `server.pem`、`server-key.pem` 和启动配置，再把新文件放到受限证书目录。发布前后执行 HTTP/TLS 健康检查，并保存证书指纹和 `/health` 响应。
4. 从干净提交启动服务。服务启动日志会记录证书到期时间；离到期少于 30 天时记录 WARNING，`/health` 和 `/__local__/health` 的 `certificate.status` 为 `warning`（过期、无法读取则分别为 `expired`、`error`）。

## CA 轮换

1. 使用受限目录中的 `analysis/ljjc-local/certs/new-20261103/ca-key.pem` 管理新 CA；不要重新生成或替代当前 CA。旧 CA 在所有隔离客户端完成切换前保留。
2. 用新 CA 签发服务端证书，仍使用上述 SAN，并完成链验证和健康检查。
3. 将新 CA 转成 DER，命名为 `4F2AF6478AB96825ABC77F2FCE9AE5BD487E29B9.cer`，按 `prepare-avd.ps1` 的现有流程复制到隔离模拟器应用数据目录的 `.config/.mono/certs/Trust/`（或该脚本解析出的 `files/.config/.mono/certs/Trust/`），设置应用 UID、权限和 SELinux 上下文。旧 CA 在切换完成前保留。
4. 用原版签名 APK 在隔离账号上验证 TLS 握手、启动配置和 `/health`。记录截图、请求日志和 logcat；没有这些证据只能记为“仅自动化”。
5. 确认所有隔离客户端已切换后，撤下旧 CA 的信任文件，归档旧 CA 和服务端证书，并更新启动配置中的指纹。

轮换脚本必须在执行前检查 `analysis/ljjc-local/certs/new-20261103/ca-key.pem` 存在且权限受限、证书 SAN 完整、服务端证书到期不晚于 CA，并在失败时停止，不得回退到自签或跳过校验。`start-committed-release.ps1` 需要用 PowerShell 7（`pwsh`）运行；Windows PowerShell 5.1 会因内嵌 Python 校验的引号处理报错。
