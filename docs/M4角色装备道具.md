# M4 角色、装备、养成与道具（本地沙盒）

本阶段把客户端能调用的角色、装备、道具和养成接口接到本地 SQLite 状态与 `LocalEconomy._change_resources` 账本。所有数值均为离线沙盒规则；`ActorLevel`、`ActorStar`、`ActorFavour` 等抽取表在当前 APK 样本中缺行，因此没有把缺失数据冒充官方数值。

已覆盖的本地操作包括：

- 角色升级、升星、锁定、分解、技能学习/已读、皮肤选择、好感/赠礼。
- 角色点赞和角色继承（含跨角色继承）使用本地事务：继承会复制等级、星级、技能和好感，并迁移装备归属；点赞按账号幂等持久化，支持取消。
- 装备强化、锁定、穿戴/卸下、分解、装备方案保存。
- 道具发放、列表、使用、出售；基础资源查询、资源合成和新资源标记。
- 勋章、封印格/奖励、角色培养进度、芯片兑换。
- 抽卡信息、抽卡交易、抽卡商店、保底验证和剧情表情查询；抽卡次数、记录与已看表情按账号持久化，统一使用本地金币和本地道具奖励。

状态保存在 `local_system_state`，资源变化统一经过经济模块的资源账本；资源不足返回 HTTP 409，锁定对象不能分解，重复领取和重复消费不会静默成功。响应优先使用 APK 描述符中存在的 protobuf 类型，未恢复描述符的活动/兑换接口返回结构化本地 JSON。

当前本地规则：角色升级每级消耗 100 金币，装备强化每级消耗 50 金币，技能学习消耗 100 金币，角色好感赠礼使用对应道具（省略道具时消耗 10 金币），角色继承消耗 500 金币，资源合成按 3 换 1。上述规则用于可玩性和事务验证，不代表已反推出的官方配置。

装备穿脱、装备方案、皮肤解锁、资源详情、封印和抽卡验证都优先返回恢复出的 protobuf 类型；descriptor 不完整的入口继续使用带 `sandbox` 标记的 JSON 兼容响应。`GachaVerify` 与 `GachaPlotEmote` 只读取或写入本地状态，不连接支付或远程抽卡服务。

## M4.7 商店刷新沙盒

`/fci/Shop/<shopId>/Goods` 支持真实 `ApiShopGoods` 请求的 GET/POST。POST
返回 `ApiShopGoods.post`，刷新会清空本地商品购买次数并持久化
`refreshCount`、`nextRefreshTime` 和 `nextFreeRefreshTime`；到达本地服务器的
06:00 日切时，下一次 GET 会自动刷新商品。每日免费刷新和付费刷新均为本地
规则，新账号和每次 06:00 日切后各有一次免费刷新；付费刷新每次消耗 10,000
金币（单次最多 10 次）；不接受任何平台支付或
远程商城数据。该价格和商品目录是沙盒策略，不代表官方配置。

## M4.9 玩家信息沙盒

`profile_features.py` 和 `systems.py` 现在持久化玩家信息入口：等级、社交头像/性别、主页背景、看板、想要的角色、角色/装备/小说收藏、小说封面、角色手账和表情。能从 `playeraction.proto` 安全解析的接口继续返回 protobuf；该文件语法字段损坏、无法安全加载的接口返回同名 camelCase JSON 兼容对象，并明确带 `sandbox` 标记。

看板保留锁定检查；本地请求可显式提供 `unlockedSignboardId` 以预览已恢复的配置项。玩家资料与收藏写入 `local_profile_features` 或既有 `game_profiles`，重启服务后仍保留。验证用例见 `tests/test_systems.py` 的 `test_player_profile_level_background_collections_and_signboard_persist`，以及 `tests/test_systems_maintenance.py` 的角色点赞/继承用例。
