# 工具链锁定（M0.3）

本文记录本地离线版的可复现工具链。版本以实际安装环境为准；变更版本时
先更新本文，再重新跑单元测试和客户端冒烟测试。

## Python

- Python 3.12（推荐使用项目目录下的 `.venv`）
- 依赖清单：项目根目录 `requirements.txt`

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install --upgrade pip
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

运行服务端时，工作目录必须是项目根目录，使 `data/descriptor_set.pb` 和
本地默认数据的相对路径保持一致。

## Android SDK / JDK

当前 SDK 根目录：`C:\Users\Administrator\AppData\Local\Android\Sdk`。

可用的 JDK 21：
`C:\Users\Administrator\.gradle\jdks\eclipse_adoptium-21-amd64-windows.2`。

在 PowerShell 中使用 SDK 工具：

```powershell
$env:JAVA_HOME = 'C:\Users\Administrator\.gradle\jdks\eclipse_adoptium-21-amd64-windows.2'
$sdk = 'C:\Users\Administrator\AppData\Local\Android\Sdk'
& "$sdk\cmdline-tools\latest\bin\sdkmanager.bat" --list
& "$sdk\cmdline-tools\latest\bin\avdmanager.bat" list avd
```

如果机器上的 command-line tools 不是 `latest`，使用 SDK 下实际存在的版本目录。

## Android 构建和模拟器

- 现有开发 AVD：`DJWK_LJJC_API30`，端口 `5560`，不要删除或 `pm clear`。
- ROADMAP M0.4 目标 AVD：`LJJC_Offline_API28`，Android 9 / API 28 / x86，端口 `5562`。
- 原版 APK 只有 32 位 `armeabi-v7a` 和 `x86` 库，模拟器验证必须选 x86 镜像。
- 音频兼容验证可用 emulator 参数 `-no-audio`；该参数只对新启动的模拟器进程生效。

## APK 和逆向工具

- apktool 3.0.3：只读输入 APK，输出到 `client-patch/work/`。
- Android build-tools 37：`aapt2`、`zipalign`、`apksigner`。
- Il2CppDumper：用于 metadata v23 结构导出；不把生成物提交到仓库。
- Ghidra 12.1.4：用于原生库伪代码和符号分析。
- UnityPy、protobuf、lz4：由 `requirements.txt` 锁定范围，服务端和抽取工具共用。

## 可复现检查

在干净终端执行以下命令，确认工具链可见：

```powershell
python --version
java -version
& "$sdk\platform-tools\adb.exe" version
& "$sdk\emulator\emulator.exe" -version
& "$sdk\build-tools\37.0.0\zipalign.exe" -h

# 项目内的一键检查（API 28 镜像尚未准备好时不加 -RequireApi28）
.\tools\verify-toolchain.ps1
.\tools\verify-toolchain.ps1 -RequireApi28
```

## 初始化和环境探测

`tools/bootstrap-toolchain.ps1` 是可重复运行的工具链 bootstrap。默认模式是
只读 dry-run：它会探测 `JAVA_HOME`、`ANDROID_SDK_ROOT`/`ANDROID_HOME`、PATH
中的 Python、SDK command-line tools、已安装的 build-tools 和 API 28 x86
镜像，并输出 JSON 报告。它不会调用网络安装器，也不会读取 APK、存档、账号
数据库或签名材料。

```powershell
# 只探测，不安装；缺失项仍会列出建议命令
.\tools\bootstrap-toolchain.ps1 -Output runtime\toolchain-bootstrap.json

# 把 API 28 镜像也视为必需项，并在缺失时以非零退出
.\tools\bootstrap-toolchain.ps1 -RequireApi28 -Strict
```

只有显式传入 `-Install` 才会调用项目 `requirements.txt` 的 pip 安装和
`sdkmanager`。安装目标只包含 Python 依赖、platform-tools、emulator、
Android 28 platform、build-tools 37 和 API 28 x86 system image；安装前应
确认 SDK 路径和 Android 许可提示。

```powershell
.\tools\bootstrap-toolchain.ps1 -Install -RequireApi28 -Output runtime\toolchain-bootstrap-install.json
```

脚本会自动选择 SDK 中最高的已安装 build-tools 目录；传入
`-BuildToolsVersion 37.0.0` 可以固定版本。`-SdkRoot`、`-JavaHome`、
`-Python` 可用于隔离环境，避免依赖机器上的硬编码路径。

不要把原始 APK、签名私钥、模拟器用户数据、请求日志或账号数据库加入 Git。
