## 硬性规则

1. **完成的标准**：真实客户端原生界面走通操作 → 结算 → 重登，附截图、请求日志、logcat 时间点。只有自动化测试的项，一律记为“仅自动化”。
2. **全量测试**：必须在**要发布的那个提交**上跑，0 失败，日志里写明提交号。不得删除测试或放宽断言；测试过期的，按客户端 Lua 的真实路由或协议改正。
3. **数值来源**：原版值优先（客户端表 / 协议枚举）；只在服务端的值，用公开资料并注明出处；两者都没有，才用本地规则，并写进 `docs/本地规则清单.md`。规则清单里不得写与事实不符的说法（例如“用户选择了 12 小时”“无原表”“D1 已实现”）。
4. **客户端补丁**：不得删除原有内容和功能入口，只能新增分支。v4–v7 中删掉的原代码（`iaphandler` −58、`purchaseactivitygift` −22、`auth` −13（含手机 / 邮箱入口检查）、`login` −8），逐个说明删掉了什么；删到入口的，改回“保留原逻辑 + 新分支”。
5. **验收环境**：只用隔离模拟器和隔离账号。不得动用户的 5560 模拟器和正式存档。
6. **演练服**：必须跑要发布的提交，补丁地址和 `public_base_url` 指向它自己的端口（19081/19103），不能靠模拟器端口映射。
7. **分支和发布**：
   - 废弃分支 `codex/fix-v9-auth`（`f1b0ed3`），它与 master 上的 `4467b12` 是重复的。
   - 每次发布：前后备份 → 资产比对 → HTTP/TLS 健康检查 → 从固定提交构建补丁并核对哈希。
