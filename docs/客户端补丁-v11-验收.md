# 客户端补丁 v11：保留原分支并修复福利三页（2026-11-02）

状态：源码和离线行为测试已完成；构建、发布和用户验收记录由发布批次补充。不能用本文件代替原生客户端验收。

## 变更范围

累计配置 `client-patch/hot-update/modules-v11.json` 保留 v10 的全部 21 个模块，将 Auth 与 IAPHandler 指向新源码 `auth-v11.lua`、`iaphandler-v11.lua`，另增加 Welfare2 的三个福利模块，共 24 个模块。v4–v10 的历史源码、配置和默认 `modules.json` 均不修改。

本地分支仅匹配 `RestifizerManager.AccountServerUrl` 的明确回环端点：HTTP `127.0.0.1` / `localhost` 的 19080、19081，HTTPS 对应 19102、19103，允许末尾一个 `/`。路径、外部域名和相似域名不匹配。原生账号和 SDK 分支仅被保留，离线测试不会连接外部账号或支付服务。

## 早期删除代码逐项核对

| 模块 | 旧删除或替换的内容 | v11 处理与理由 |
|---|---|---|
| Auth | `GetEntryType` 将 phone/email 分类替换成统一 password；`RequestAccountAuth` 将原 `ApiAuthInfo` 改成 `/Account/` → `/Auth/` 本地 JSON | 还原非本地端点的原 phone/email 校验（含 `name+tag@example.com`）及原 `ApiAuthInfo` 请求。明确本地端点保留 3–64 位本地用户名和既有注册/登录；本地规则与服务端用户名校验保持一致。64 位输入和 v9 错误提示保留。 |
| IAPHandler | `UseRemoteProduct` 恒 false，`Refresh` 删除 SDK 刷新，`GetActivityInfo`、`PurchaseImpl`、`GetLocalizedPrice`、`MidasProxy`、`SyncMidas` 无条件走离线替代 | 七个函数均恢复非本地端点的原函数体。本地端点继续使用当前价格表、购买活动 HTTP、下单/到账及本地回调，不调用平台 SDK 或 Midas 同步。 |
| PurchaseActivityGift | 删除两处“只更新首个同商品 Mall 行”的代码，改用 `SetProductBuyCount` | 属于同商品卡片同步修复，不是删入口。`GetMallInfoByProductID` 原函数仍保留，事件注册、购买按钮、活动读取及原始卡片展示仍存在；已有测试覆盖 834/860 同商品的全部可见卡片更新。v11 不再改该文件。 |
| Login | 原 `ProcessLogin` 中无区分地 MSDK 自动登录改为账号类型分流；`OnAccountAuthResponse` 内保存缓存代码抽到 `SaveAccountAuthResponse` | 原 QQ/微信按钮和 MSDK 分支保留；本地 password/guest 增加独立缓存登录；缓存保存和成功广播仍执行；原本为空的 `ShowAccountAuthWindow` 已接入 Auth。是增加本地账号路径和抽取 helper，不是删除功能入口。v11 不再改该文件。 |

原始 Lua 来源及原/新源码 SHA256 见 `client-patch/hot-update/source-origins-v11.json`。旧模块的来源继续由历史来源文件记录。

## 福利三页：原资源证据与修复

离线使用 UnityPy 读取 `analysis/ljjc_manifest_out/assets/Patch/assetbundle/window/` 中的原 prefab。`welfare/welfare` 的 LuaInjector 路径是 `Window/Welfare2/Welfare2`，因此修复目标是 Welfare2，并未根据旧 Welfare 的 Animator 差异猜改动画。

| 页面 | 原文件证据 | v11 处理 |
|---|---|---|
| 夏日拼图 | `welfare/wlfpostcard` 内 Main、Detail 的 `m_IsActive` 都是 true；Detail 下存在未初始化的 BlockIcon 碰撞体。原 `WlfPostcard.OnEnable` 仅调用 InitContent，未先隐藏详情。 | 每次进入先清当前选卡、显示 Main、隐藏 Detail 与 FullScreen，再读原数据；点击点亮仍使用原 `fci/Postcard/Lighten/<id>` 请求。删除空失败回调，使错误走现有统一提示。原交互是点击瓶子/卡片后点击碎片，不是拖动刮卡。 |
| 练度转移 | `welfare/wlfdecrepittransport` 指向 `Window/Welfare2/WlfDecrepitTransport`。原 Lua 只有 InitData；旧 Welfare 曾调用它，Welfare2 的动态创建流程未调用，按钮所读的 m_transportObjs 一直未初始化。 | 增加 OnEnable 从活动管理器读取活动后执行原 InitData；每次点击更新持有角色列表。只使用原 DiffActorInherit 33001：1008 → 1007 / 1018；保留原选角窗口、锁定和编队校验。 |
| 真爱之契 | `welfare/wlfconditionreward` 的 ConditionRewardTexture：`mTexture.m_PathID=0`、`mMainTexturePath=""`；按钮的图集和 sprite 也为空。原 Lua 不赋图。原包中 `texture/welfare/ture_love` 存在，提取确认画面含“点击选择”。 | 将原纹理绑定到已有 UITexture；沿用原 ManualBoxActor 选择界面。奖励缓存尚未准备好时先请求原 `fci/conditionreward`，收到资格和盒子后再打开，避免 reward.id 空引用。 |

三个脚本沿用原 UI 与活动规则，不增加赠送、不放开任意角色继承，也不改 prefab 或 Animator。以上是离线复现与修复依据，实际点击、动效和显示仍由用户原生验收确认。
