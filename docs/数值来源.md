# 服务端数值来源

本地版把客户端可观察的配置和服务端必须补充的规则分开保存。`data/config/` 是从 APK/运行时样本抽取的配置；`data/server-only/` 是本地兼容服务使用的补充规则。

| 文件 | 内容 | 来源 | 可信度 | 备注 |
|---|---|---|---|---|
| `data/local-defaults.json` | 新玩家初始角色、体力、金币、教程 ID | `analysis/ljjc-local/config-samples-live.jsonl` | C | 文件内已标注为本地测试默认值 |
| `data/config/Misc.json` | 每日刷新、抽卡和上限等运行时字段 | 客户端运行时样本 | C | 原服务端可能在热更新中覆盖 |
| `data/config/ChapterInfo.json` | 章节和关卡索引 | `config-samples-live.jsonl`、`story-config.json` | C | 部分章节资源仍待完整核对 |
| `data/server-only/economy.yaml` | 本地经济初值、沙盒抽卡/商城规则 | 上述样本的兼容性归纳 | C | 不是官方概率公示 |
| `data/server-only/activity-schedule.yaml` | 离线活动循环排期 | 本地策略 | D | 历史活动时间线未恢复 |
| `data/server-only/historical-evidence.yaml` | 公开历史公告/攻略中的停运、活动窗口和活动规则证据 | TapTap、3DM 公开页面（见文件内 URL） | C | 仅作证据索引，不自动覆盖本地规则 |

可信度为 `D` 的条目只用于让离线客户端有确定行为，后续拿到公告、录像或玩家存档后应逐条替换并保留来源记录。真实支付、官方账号和远程服务不属于这些数值来源。

## M2.7 机器审计

`tools/audit_server_values.py` 会遍历 `data/server-only/*.yaml` 的每个叶子值，继承文件级
`provenance` 并检查 `source`、日期和 `confidence`。报告写入
`data/server-only-value-audit.json`。当前 4 个规则/证据文件的叶子值都有来源和可信度标记；
运行时样本和公开历史资料都只标为 `C`，本地兼容策略标为 `D`，没有值被标记为官方 A/B 级。
`historical-evidence.yaml` 不参与服务运行，只为后续把本地规则替换成有出处的历史值保留可追溯依据。
这份报告只证明元数据完整，不提升数值本身的历史可信度。
