# 异步竞技场副本配置证据

本次专项核对客户端依赖和可加载副本，并补充显式关闭的原生路由边界，不配置猜测性的副本 ID。

## 客户端调用链

- `analysis/lua-decompiled/window__asyncpvp__asyncpvp.lua`：
  - 读取 `fci/tournament/info/{activityType}/{activityId}` 和 `fci/tournament/summary/`；
  - 进入 `fci/tournament/enter/{activityType}/{activityId}`；
  - 对战前 `fci/tournament/dungeonenter/`，请求带 `tournamentId`、`activityType`、`target_uid`；
  - 返回的 `dungeonUid`、`dungeonId` 直接传给 `WU.EnterGameLevel(..., DungeonType.AsyncPvp)`。
- `analysis/lua-decompiled/scene__scenefight.lua`：异步竞技场结算先 PATCH `fci/tournamentdungeon/{uid}/active/`，再 POST `fci/tournament/dungeonbalance/`。
- `data/descriptor-audit.json`：`ApiTournamentDungeonEnter.result` 只有 `dungeonUid` 和 `dungeonId`，无法从协议推断副本配置。
- `analysis/ljjc-local/protocols/interfaces.json`：`RefreshPriceType_AsyncPvpRefreshTarget=10005`；对应 `data/client-tables/RefreshPrice.json` 的消耗是物品 `80001`。物品 `80003` 出现在刷新价类型 `18`，不是异步竞技场刷新类型，不能作为该玩法的票据依据。

## 原生资源依赖

`SceneFight.ConfigStage` 的 IL2CPP 调用审计记录（分析阶段生成的 `runtime/tournament-research/native-calls.json`）显示调用链为 `XlsxData.get_DungeonMonster` → `XlxsDataDungeonMonster.Get` → `DungeonMonster.get_StageID/MusicID` → `LoaderStage.LoadGameStage` → `ResourceManager.GetBytes`。该记录属于审计过程产物；结论是可复核的调用链本身，而非服务端配置。返回没有客户端资源和 `DungeonMonster` 行的 ID，客户端不能进入可验证的战斗。

APK 清单的资源路径能证明存在场景加载器和配置包，但不证明活动配置选中了哪一行：

- `analysis/ljjc_manifest_out/assets/Patch/assetbundle/data/scenefile/scenes*_xml`；
- `analysis/ljjc_manifest_out/assets/Patch/assetbundle/data/stagefile/stage_*_xml`；
- `analysis/ljjc_manifest_out/assets/Patch/assetbundle/data/xlsx/dungeonmonster`（FCI 保护的完整包，916 行）。

已观察的 `DungeonMonster` 候选包括 4001–4030（`modeIndex=4`、`Stage_01`–`Stage_07`、`team_ai_3`、affix 2407）、3001、7001、9999 等。现有证据没有把这些 ID 与 `ActivityType.Tournament_AsyncPvp=5` 绑定；`data/config/DungeonMonster.json` 只有 1–4 的部分运行时样本，`docs/内容清单.md` 也明确标为部分证据。

## 必须保持的边界

在取得真实 `TournamentConf.DungeonId` 或真实 `dungeonenter` 响应前，服务端可以提供活动信息、机器人对手和记录接口，但 `dungeonenter` 必须报告未配置并拒绝进入；不能把 4001、3001、7001、9999 或其他故事/竞速地图当作异步竞技场地图。这样可以避免客户端加载错误关卡、使用错误 AI 或在结算时产生不可追溯奖励。

## 已实施的路由边界

`tournament.py` 先于旧 `systems.py`、`social.py`、`dungeon.py` 分发：真实 `activityType=5` 的入场、对手、战斗和结算请求返回 `501 tournament_asyncpvp_not_configured` 与 `dungeonConfigured=false`；`GET /fci/tournament/summary/` 返回协议允许的空 `activityInfo`。这样真实 `POST /fci/tournament/enter/` 不会误创建旧 PvE 兼容关卡 `900301`，也不扣资源或写入战斗记录。入场识别兼容 JSON 与 `ApiTournamentEnter` 二进制请求。

未带原生活动字段的旧本地 PvE 路由、其他活动类型的共享路由、BurstLink、RacePVP 和登录期 `asyncpvprecord` 由原处理模块继续负责；本次没有添加猜测性机器人页、门票或奖励。
