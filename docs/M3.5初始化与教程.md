# M3.5 初始化与教程（本地沙盒）

本地服务端现在按可验证配置创建新玩家，并保存教程状态。`PlayerInitConfig.json` 的
`observedCount` 为 0 且抽取记录报错，因此没有把缺失的官方初始角色、资源或奖励写入
服务端。当前 `data/local-defaults.json` 中的角色、资源和看板是明确标注的本地兼容策略。

`PlayerLevelInitConfig.json` 的第一个观测行提供了初始等级 1，`game.py` 会读取这个值，
缺少配置时才回退到本地默认值。教程 ID/顺序来自 `Tutorial.json`；由于该表只有 6/55
观测行，剩余 ID 使用同一份本地默认清单，不能视为完整官方教程表。

客户端 `Manager_TutorialManager.lua` 会为每个 `TutorialStep` POST
`/fci/tutorial/<id>/<step>`，完成时 PUT `/fci/tutorial/<id>` 并携带
`status`/`stepForceFinish`。服务端将最高已到达 step 持久化到
`game_profiles.tutorial_steps_json`，重复请求幂等，重启后可恢复；PUT `status=0` 会重置
该教程的 step。完成状态仍按配置顺序门控，不能跳过前置教程。

名字校验使用观测到的 `Misc.maxNameLen=7`；过长名字返回结构化错误，本地重复名字返回
`409 name_taken`，避免客户端显示名与存档不一致。

验证：`tests/test_game.py`、`tests/test_systems.py`、`tests/test_systems_maintenance.py`
及全量 pytest 均通过。上述行为是本地兼容子集，未宣称恢复官方缺失数据。
