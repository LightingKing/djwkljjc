# 契约测试与流量回放

M3.8 的测试入口是 `tools/contract_harness.py`。它把接口契约表当成测试清单，而不是把“客户端曾经调用过”误报成“服务端已经恢复”。

## Smoke 流程

每个接口取一条确定性的请求样例，选择第一个 route 别名，并用安全的占位值填充路径参数。未注册的接口期望得到 `501`，响应为 `route_not_implemented`；注册的接口可以在 replay 记录中把 `expectedStatus` 改成它的实际成功状态。

```powershell
python tools/contract_harness.py --write-sample-replay dev/contract-smoke.jsonl --report dev/contract-smoke-report.json
```

报告包含 `total`、`passed`、`failed`、`ok` 和逐条结果。路径参数和请求字段均为固定样例，不会读取或生成真实账号凭据。

## JSONL 回放

每行是一个对象：

```json
{"interface":"ReqDir","method":"POST","path":"/Dir/","request":{},"expectedStatus":501}
```

`expectedStatus` 省略时默认为 `501`，适合当前尚未接入的接口。`404` 可以用来验证未知路径；回放结果会把状态码和安全响应一起记录在报告中。回放在内存中的 `RouteRegistry` 上运行，不连接远程服务器。

```powershell
python tools/contract_harness.py --replay data/golden-traces/example.jsonl
```

正式接入接口后，为它注册真实处理器并在对应 replay 记录中设置期望状态，再把响应字段断言加入该接口的专项测试。这样覆盖率会随着路由注册自然增长，未实现接口仍保持可观测的 501。
