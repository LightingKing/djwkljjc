## 执行总原则（必须遵守）

1. **入口一律开放，不因缺数据而关闭。** 原版数据缺失时：
   - 先查公开资料（2018–2019 攻略、贴吧、NGA、B 站、TapTap、官方公告），实现时在代码注释和 `docs/本地规则清单.md` 里写明出处（URL、日期、置信度 A/B/C）；
   - 查不到的，按"尽量贴近原版"定本地规则并标注置信度 D，**照样开放**，同时列进 `docs/本地规则清单.md`（每条写：内容、依据、可调参数、默认值），由用户事后确认或调整。
2. **错误回包不能让客户端重置。** 客户端通用错误处理读 `error.code` 并在点确定后 `ResetGame()`（`manager__restifizermanager.lua:251-259`）。所有拒绝类回包统一改为客户端能显示的格式：`{"error":{"code":"<已有本地化键>"}}` 或原版 notify 形式（509/507 只弹提示）；确实可预期的拒绝优先用"只提示不重置"的形式。见 A4。
3. **测试必须用客户端真实请求体**：包括 `Post({})` 实际发出的 JSON `null`、wireformat、带查询参数的 HTTP 入口；禁止在测试里手写状态绕过真实链路（本轮有两处这样掩盖了缺陷，见 A20）。
4. **每项都要模拟器实测**（截图 + 请求日志存到证据目录）；做不到的必须在执行记录里写明"仅自动化验证"。
5. 用隔离副本账号测试，不在真实账号上做测试性购买；开工前、发布前各备份一次存档；发布后核对真实存档资产不变。
6. 并行时同一文件只允许一个执行单元修改；新功能做成独立模块，`game.py`/`server.py` 接线集中做。
