# 时钟与重置

M3.4 提供 `server/core/clock.py` 作为本地服务端的时间基础设施。业务模块应通过 `ServerClock.now()` 取得服务器时间，不要在功能代码里直接调用 `time.time()`。

`ServerClock` 默认读取当前系统 Unix 时间（UTC），也可以注入一个 `source` 用于测试，并使用 `set_offset()` 或 `adjust()` 设置本地时间偏移。偏移只影响运行时读数，不会改写已经保存的时间戳，因此重启后可以由管理层重新设置。

每日和每周重置以“时间桶”表示：

- `daily_key(value, refresh_at="06:00:00")` 在每天 06:00 切换日期桶，适合签到、每日任务、商店刷新和体力恢复。
- `weekly_key(value, refresh_at="06:00:00", week_start=0)` 按 ISO 星期一作为一周开始；`week_start=6` 可以切换为星期日。
- `next_daily_boundary()`、`next_weekly_boundary()` 返回下一次重置的带时区时间点。
- `period_elapsed()` 计算两个时间戳之间跨过了多少个每日或每周边界，服务端可以据此补做离线重置。

恢复计算通过纯函数 `recover_resource()` 完成。调用方传入当前余额、上次恢复时间、当前时间、上限、恢复间隔和每次恢复数量，函数返回新的余额、实际恢复量、完整间隔数和新的时间标记。它会拒绝未来时间、负余额、超过上限和非正间隔；资源达到上限时把时间标记推进到当前时间，避免以后重复追补。

服务启动时 `accounts.py`、`game.py`、`events.py` 和经济模块都接收同一个 `ServerClock`；活动排期也使用它计算窗口。服务端实例把签到等事件的每日桶设为 06:00，直接构造 `LocalGame` 的测试仍保留午夜回退，以免破坏历史单元测试。玩家 `updated_at`、签到日期、活动窗口、月卡领取日和体力时间戳都应继续在同一个写事务里应用。月卡领取读取 `LocalGame.daily_key`，因此服务启动器下的月卡也遵守 06:00 边界。

验证：

```text
python -m unittest discover -s tests -p test_clock.py -q
```
