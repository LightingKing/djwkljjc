# M2.4 IL2CPP 结构审计

本阶段已完成可复现的静态结构导出。Il2CppDumper v6.7.46 对 x86
`libil2cpp.so` 和 metadata v23 真实运行并生成了 `dump.cs`、`il2cpp.h`、
`script.json`、`stringliteral.json`。Ghidra 12.1.4 已创建工程、导入同一份
x86 native 库并保存项目；自动分析在 300 秒时限内未完成，因此这里不把它
写成“完整 Ghidra 分析”或“已完成符号重命名”。整个过程只读，没有修改 APK、
native 库、TPShell 或完整性校验。

运行命令：

```powershell
python tools/inspect_il2cpp.py `
  --metadata client-patch/output/ljjc-apk-ms7w063u/decoded/assets/bin/Data/Managed/Metadata/global-metadata.dat `
  --binary client-patch/output/ljjc-apk-ms7w063u/decoded/lib/armeabi-v7a/libil2cpp.so `
  --binary client-patch/output/ljjc-apk-ms7w063u/decoded/lib/x86/libil2cpp.so `
  --output analysis/il2cpp/structure-audit.json
```

## 已验证证据

- `global-metadata.dat` 魔数有效，metadata version 为 23，文件大小
  11,527,908 字节，32 个 v23 表范围全部在文件内。
- 两个 `libil2cpp.so` 都是有效 ELF32：`armeabi-v7a` 为 ARM，`x86` 为
  i386；两个文件均通过 `il2cpp_init`、`il2cpp_domain_get`、
  `il2cpp_thread_attach` 字符串探针。
- Il2CppDumper ZIP SHA-256：
  `f5fc60dfc5c034c1ff3fc651514416ebd47658a63493207734537fd25fa2dea`。
- `dump.cs`：18,438,202 字节，SHA-256
  `17f46856e41d149b8d9bcc55b4fd9cdb9648405f3f2db218143d4b412fd5c48d`。
- `il2cpp.h`、`script.json`、`stringliteral.json` 的大小和 SHA-256 均保存在
  `analysis/il2cpp/structure-audit.json` 的 `tooling.il2cppDumper.keyOutputs`
  中，便于复核而不依赖文件名。
- Ghidra 工程目录为
  `analysis/il2cpp/ghidra-project-x86/`，日志为
  `analysis/il2cpp/ghidra-x86.log`；日志显示导入和保存成功，输入 x86 库
  SHA-256 为
  `fd5173e4ec653d0feff23333a6908ef9042052fabe9b5b3eb5efb0f7946a5c50`。

## 明确的限制

- `dump.cs` 是静态类型/方法重建结果，不是可编译的官方客户端工程，也不能
  反推出官方服务端代码、数据库或已关闭的远程内容。
- Ghidra 自动分析在 `Non-Returning Functions - Discovered` 阶段达到 300 秒
  超时。项目和 ELF 导入证据保留，但 `analysisCompleted=false`，没有声明
  完整伪代码、函数重命名或重点类覆盖。
- metadata 表项和 ELF 字符串探针不等同于函数可调用性；仍需独立的运行时或
  客户端证据才能确认行为。
- `analysis/` 和 `runtime/` 是逆向工具/证据目录，不进入离线服务端交付包。

机器可读结果见 `analysis/il2cpp/structure-audit.json`。该结果用于把 M2.4
标为 `verified_static`：静态导出和 Ghidra 导入已被证据验证，但 Ghidra 自动
分析仍是明确的未完成项。
